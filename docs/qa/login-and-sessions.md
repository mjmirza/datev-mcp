# Login and sessions

How the DATEV login works and what to do when it asks again.

20 questions. Generated by `npx tsx scripts/build-qa.ts`. Do not edit by hand.

### Which login method does it use?

OpenID Connect authorization code flow with PKCE against DATEV's login service. The server never sees your DATEV password.

### Which DATEV account type should I use in the sandbox?

The sandbox test account DATEV gave you, usually via "DATEV-Benutzerkonto" on the login page.

### What happens after I agree on DATEV's permission page?

DATEV redirects to a one-time address on `localhost` on your machine. The login command receives the code there and swaps it for tokens.

### Why does the redirect go to localhost?

The login command starts a short-lived receiver on a free local port. Nothing is exposed to the internet.

### How long does a login last?

The access token lasts about 15 minutes and is refreshed automatically. The refresh token lasts about 11 hours and can be used once.

### Why do I have to log in again after a long break?

DATEV refresh tokens expire after about 11 hours. Run the `login` command again.

### Where is the session stored?

In `~/.config/datev-mcp/session-<env>.json` with owner-only permissions, or in `DATEV_MCP_HOME` if you set it.

### Can two assistants share one login?

Yes. Refreshes run under a file lock, so two processes normally never spend the same single-use refresh token. The lock is advisory, so in rare timing one refresh can be refused and you log in again. VALIDATION.md explains it.

### What happens if two processes refresh at the same time?

One refreshes, the other waits and then reads the new session. A process that loses the race adopts the newer session instead of deleting it.

### Does a wrong client secret log me out?

No. Only a rejected refresh token ends the session. A wrong secret shows an error and keeps the saved session.

### How do I log in on a server without a browser?

Set `DATEV_MCP_NO_BROWSER=1`. The command prints the sign-in link and you open it in any browser that can reach the machine's localhost.

### Which scopes are requested?

By default every scope the operation index knows. Set `DATEV_SCOPES` to a space separated list to request fewer.

### Why can the server not tell me which scopes I got?

DATEV does not return the granted scopes in its token answer. A missing product only shows up as a 401 or 403 on first use.

### Can I log out?

Run `datev-mcp disconnect`. It revokes the connection at DATEV and then deletes the local session. Deleting the session file alone leaves the connection valid at DATEV, so never do that. Connected apps are also listed at https://apps.datev.de/tokrevui.

### Does it support production?

Yes, with `DATEV_ENV=production`, after DATEV has approved your app for production.

### Are sandbox and production sessions kept apart?

Yes. Each environment has its own session file, and confirmation codes include the environment.

### What does `doctor` check about the login?

That a session is saved, that it yields a valid access token (refreshing it only if it is due), and that DATEV's userinfo and clients endpoints answer.

### The login page says my app is unknown. Why?

The client id is wrong or belongs to another environment. Check `DATEV_CLIENT_ID` and `DATEV_ENV`.

### The browser shows "DATEV login complete" but the terminal waits. Why?

The page appears as soon as DATEV's redirect reaches the terminal. After that the terminal still exchanges the code for tokens and waits for the session lock, up to 90 seconds, if another datev-mcp process holds it. Close other MCP clients using datev-mcp, or wait for the lock timeout message.

### Can I keep the credentials out of files entirely?

Yes. Use a launcher script that reads them from your password manager and starts the server, and point your MCP client at the launcher.
