# Limits and reliability

Time budgets, retries and size caps.

10 questions. Generated by `npx tsx scripts/build-qa.ts`. Do not edit by hand.

### How long can one call take?

55 seconds per DATEV call by default, token included, and retries only start if they still fit. This includes `datev_find_accounts`.

### Which errors are retried?

For reads 429, 502, 503, 504 and network errors, up to three attempts. Writes are never retried.

### Is Retry-After honored?

Yes, in seconds or as an HTTP date. A wait that does not fit the budget means no retry.

### What is the largest answer it reads?

50 MB at most for operation answers. Text previews are shorter.

### What happens to a body that breaks off?

Reads retry it. A truncated answer is never shown as complete.

### Do the accounting tools page automatically?

Yes. Clients page in steps of 100 and postings read every page within the budget.

### What if the budget runs out while reading postings?

The rows already read are kept and the answer says where to continue.

### How fast are typical calls?

In the sandbox on 2026-11-07 most reads answered in well under a second.

### Is there a rate limit on the server side?

Only one. At most 10,000 confirmation codes can be accepted within 15 minutes. Reads have no server-side limit. DATEV's rate limit applies and the server respects it.

### What does the server do on a malformed JSON answer?

It returns the raw text with DATEV's status. Typed tools that need JSON then fail with an error, `datev_call` passes the text through, so a 200 with broken JSON still reports HTTP 200.
