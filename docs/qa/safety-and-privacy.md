# Safety and privacy

What protects your clients' data and your machine.

20 questions. Generated by `npx tsx scripts/build-qa.ts`. Do not edit by hand.

### Can the assistant change data without me seeing it?

Through `datev_call`, `datev_upload_file`, `datev_upload_extf` and `datev_upload_document`, no. A write first returns a preview and a confirmation code, and runs only when called again with that exact code. Each code is accepted once, and a failed send needs a new preview. One exception: `datev_account_postings` starts DATEV's postings export job directly, because that job only builds a report and changes no bookings.

### What is the confirmation code bound to?

An HMAC over the exact request, including tool, environment, operation, parameters, body, and for files their name, type and SHA-256. It is valid for 15 minutes.

### What if the assistant changes the file after the preview?

The code no longer matches and the write is refused. The assistant has to show a new preview.

### Can a write be sent twice by accident?

Writes are never retried, except after a 429 where DATEV refused the request and cannot have applied it.

### Can the assistant upload my SSH keys?

No. Files in hidden folders and names that look like keys or credentials, such as `.env`, `*.pem`, `id_rsa` or `credentials.json`, are refused.

### What about a symlink that points into `~/.ssh`?

A link is judged by where it really points, so it is refused too. The file is opened once without following links and must be the file that was checked.

### Can a download overwrite an important file?

Saves never follow a link, never land in a hidden folder, create new files with owner-only permissions, and replace existing files only with `overwrite: true`.

### Can the client secret leak through a redirect?

Operation calls never follow redirects, and their base URLs come only from DATEV's own specs. The login token request and `doctor` use fetch's default handling and would follow one. They start at DATEV's configured login endpoints, and `doctor` also calls the accounting-clients API.

### Can a request be pointed at another host?

No. Path values are checked against DATEV's schema and may not contain `/`, `..` or separators that would shift the request.

### Does the server keep my clients' data?

It keeps charts of accounts in memory while it runs, reused for 10 minutes. Expired entries stay in memory until replaced or the server stops. Files you save with `save_to` or create with `datev_write_extf_batch` stay on your disk. Login tokens are also stored locally, owner-only.

### Are tokens ever logged?

No. The session file is owner-only and tokens are never written to logs or tool answers.

### What does the server not protect against?

A compromised machine, an assistant you allow to confirm writes without reading the preview, and DATEV itself. SECURITY.md lists every known limit.

### Who reviewed the security?

A second AI model attacked the code in four passes. 46 of 48 findings were fixed with tests and two known limits are documented.

### How do I report a vulnerability?

Privately through the repository's Security tab, "Report a vulnerability". Please do not open a public issue.

### Does it send data anywhere besides DATEV?

Operation calls go only to the DATEV hosts in DATEV's specs and never follow redirects. The login token request and `doctor` start at DATEV's endpoints but use fetch's default redirect handling. What your AI provider receives depends on your assistant, which is why COMPLIANCE.md asks for a data processing agreement.

### Is client data sent to the AI model?

Answers from DATEV go into your conversation, so your AI provider processes them. Only use real client data after you have the agreements in COMPLIANCE.md.

### Can a huge answer crash the server?

Operation answers are read as a stream and reading stops at the cap, at most 50 MB, and a cut answer is marked as truncated. The login token request and `doctor` read their small answers without that cap.

### Can a header be injected into a request?

No. Server-set headers cannot be overridden and any header value with a line break is refused.

### Is there a kill switch for writes?

Writes through `datev_call`, `datev_upload_file`, `datev_upload_extf` and `datev_upload_document` never run without a confirmation code, so declining the preview stops them. `datev_account_postings` starts DATEV's read-only postings export job without a preview. Your MCP client can also require approval per tool call.

### Are the dependencies audited?

Runtime dependencies are the MCP SDK, zod and an MIT EXTF library. Dependabot watches them and CI runs gitleaks on every pull request.
