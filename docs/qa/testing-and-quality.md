# Testing and quality

How the claims in this repository are checked.

10 questions. Generated by `npx tsx scripts/build-qa.ts`. Do not edit by hand.

### How many tests are there?

Over 100 unit and integration tests and 28,496 offline scenarios across all 209 operations. `npm test` and `npm run eval` print the current counts.

### What are the offline scenarios?

Generated checks per operation for URLs, headers, bodies, retries, time budgets, cancellation, binary downloads and size caps, against a fake DATEV.

### How do you know the scenarios catch bugs?

Bugs were planted in the client on purpose. All three were caught, with 440 failing scenarios, and the code was restored after.

### Was it tested against the real DATEV sandbox?

Yes. A paced live sweep reached 71 read operations and a live tour of the tools passed, including an EXTF import DATEV accepted.

### Why are write operations not swept live?

They change data, even in the sandbox. Writes are covered offline and by the confirmed live import.

### What runs in CI?

Typecheck, unit tests, the offline eval, a build, knip for dead code, and on pull requests a gitleaks secret scan.

### Where are the reports?

`docs/VALIDATION.md` explains the method and `docs/evidence/` holds the reports from 2026-11-07.

### How do I run the tests myself?

`npm test` for unit tests and `npm run eval` for the offline scenarios.

### How do I run the live checks?

`npm run test:live` for a short tour and `npm run sweep` for the paced crawl. Both need a sandbox login.

### Are there property-based tests?

Yes, with fast-check, for example for fiscal year id shapes, NDJSON round trips, job states, account prefix search, path encoding and EXTF batches.
