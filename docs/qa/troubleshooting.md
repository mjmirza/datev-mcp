# Troubleshooting

What an error means and what to do.

30 questions. Generated by `npx tsx scripts/build-qa.ts`. Do not edit by hand.

### I get HTTP 401. What does it mean?

DATEV did not accept the token for that product. Usually the app is not subscribed to the product or the scope was not granted. Check the subscription in the portal and log in again.

### I get HTTP 403. What does it mean?

DATEV refused access to that resource, often because the client or service is not enabled for your app or user.

### I get HTTP 404. What does it mean?

The resource does not exist, for example a client id or job id that the test data does not have.

### I get HTTP 400. What does it mean?

DATEV rejected the request content or, in the sandbox, the product is not enabled for that client. The answer body has DATEV's reason.

### I get HTTP 429. What does it mean?

DATEV's rate limit. Reads retry by themselves, honoring Retry-After. Wait and try again.

### I get HTTP 500 "Sandboxing policy error". What does it mean?

DATEV's sandbox gateway refuses that resource for your app. Ask DATEV to enable the product.

### I get 502, 503 or 504.

DATEV's gateway had a temporary problem. Reads retry up to three attempts within the 55 second budget.

### The answer says "Ran out of time".

The call did not finish within its 55 second budget. Narrow the request, or continue a postings job with `job_id`.

### The answer says "DATEV login needed".

The refresh token expired or was used up. Run the `login` command again.

### The answer says an operation is missing from the operation index.

The index was not built or is from another download. Run `npm run specs` and `npm run build`.

### `doctor` fails on credentials.

`DATEV_CLIENT_ID` or `DATEV_CLIENT_SECRET` is not in the environment. Start with `node --env-file=.env/.env.local` or your launcher.

### `doctor` fails on the operation index.

Run `npm run specs`. It downloads DATEV's specs and rebuilds `src/data/operations.json`.

### `doctor` fails on the saved session.

Run `login` once.

### `doctor` fails on userinfo.

The token was refused. Log in again. If it keeps failing, check that the app and environment match.

### The assistant says a list is empty but I expected data.

An empty list can mean DATEV has no records, or that `datev_find_accounts` skipped account rows it could not read, or that `datev_account_postings` skipped posting rows without a readable account number while filtering by account. Errors are not turned into empty lists. Check the client id and fiscal year, and try `datev_call` to see DATEV's raw answer.

### A typed tool says the answer has an unknown shape.

DATEV answered with data the tool does not recognize. The tool refuses it rather than guess. Open an issue with the operation id.

### The tool says the answer was truncated.

It hit the size cap. For `datev_call`, ask for fewer records with the operation's own paging or filter parameters. Sums and balances and postings download DATEV's full answer before filtering, so a prefix, a smaller limit or another account does not help there. Try a different fiscal year.

### The upload says the confirmation code does not match.

Something in the request changed after the preview. Ask for a new preview and confirm that one.

### The upload says the code expired.

Codes last 15 minutes. Ask for a new preview.

### The tool refuses my file path.

The path is in a hidden folder, looks like a key file, or is a link to one. Move the file to a normal folder.

### The tool refuses `save_to` because the file exists.

Pass `overwrite: true` if you really want to replace it.

### Login works but every product returns 401.

DATEV does not report granted scopes. Check that each product is subscribed in the portal, then log in again so the new scopes are requested.

### Postings keep returning `ready: false`.

DATEV's job is still running. Call again with the same `job_id` a little later.

### The server does not show up in my MCP client.

Check the command path is absolute and that the build exists in `dist/`. Run the command by hand to see the error.

### The server starts but tools fail with missing credentials.

Your MCP client does not pass the environment. Use `--env-file` in the command or a launcher.

### `npm run specs` fails.

It downloads from developer.datev.de. Check your network or proxy and try again.

### Tests pass locally but fail in CI.

CI fetches fresh specs. If DATEV changed an API, the index changes too. Compare with `npm run index:check`.

### Where are the logs?

The server writes errors to standard error, which your MCP client usually shows in its log view.

### How do I report a bug?

Open an issue with the bug template. Include the tool, the operation id and the error text, never tokens or client data.

### How do I see what was sent to DATEV?

Use `datev_describe_operation` to see the request shape. The server does not log request bodies to protect client data.
